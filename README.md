# XWiki LXC for Proxmox VE

[![ShellCheck](https://github.com/freakms/proxmox-script-xwiki/actions/workflows/shellcheck.yml/badge.svg)](https://github.com/freakms/proxmox-script-xwiki/actions/workflows/shellcheck.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

🇩🇪 [Deutsche Version](README.de.md)

A single command on your Proxmox VE host creates a Debian 13 LXC container
and installs [XWiki](https://www.xwiki.org) in it, from the **official XWiki
Debian packages**:

- Debian 13 (trixie), unprivileged container, nesting enabled, start on boot
- Apache Tomcat 10 + OpenJDK 21
- PostgreSQL (default) or MariaDB. The database and user are created automatically
- Tomcat heap sized to about 60 % of the container RAM
- XWiki channel `stable` (default, currently 18.x) or `lts`

## Requirements

- Proxmox VE 8 or 9, run as `root` on the host shell
- Internet access from the host and from the container
- At least 2 GiB RAM for the container (4 GiB recommended) and 8 GiB disk (16 GiB default)

## Quick start

Run this on the **Proxmox VE host** shell:

```bash
bash -c "$(curl -fsSL https://raw.githubusercontent.com/freakms/proxmox-script-xwiki/main/xwiki-lxc.sh)"
```

The script asks for the most important settings, shows a summary and asks
you to confirm. When it finishes, open:

```
http://<container-ip>:8080/xwiki/
```

The XWiki **Distribution Wizard** then walks you through creating the
administrator account and installing the *XWiki Standard* flavor.

> Always read a script before you pipe it into a root shell. You can also
> clone the repository and run `./xwiki-lxc.sh` locally. It then uses
> `install/xwiki-install.sh` from the clone.

## Unattended installation

Set any of these variables and pass `--yes` to skip all questions:

| Variable | Default | Description |
|----------|---------|-------------|
| `CTID` | next free ID | Container ID |
| `CT_HOSTNAME` | `xwiki` | Hostname |
| `CORES` | `2` | CPU cores |
| `RAM` | `4096` | Memory in MiB |
| `SWAP` | `512` | Swap in MiB |
| `DISK` | `16` | Root disk in GiB |
| `STORAGE` | first storage with `rootdir` | Storage for the root disk |
| `TEMPLATE_STORAGE` | first storage with `vztmpl` | Storage for the Debian template |
| `BRIDGE` | `vmbr0` | Network bridge |
| `IP` | `dhcp` | `dhcp` or CIDR, e.g. `192.168.1.50/24` |
| `GATEWAY` | – | Gateway for a static IP |
| `DNS` | host settings | DNS server(s) |
| `VLAN` | – | VLAN tag |
| `UNPRIVILEGED` | `1` | `1` = unprivileged container |
| `CT_PASSWORD` | – | Root password (otherwise use `pct enter <id>`) |
| `SSH_KEY_FILE` | – | Public SSH key file for root |
| `DB` | `pgsql` | `pgsql` or `mariadb` |
| `XWIKI_CHANNEL` | `stable` | `stable` or `lts` |
| `JAVA_XMX` | ≈ 60 % of `RAM` | Java max heap in MiB |

Example:

```bash
CTID=150 RAM=6144 DISK=32 IP=192.168.1.50/24 GATEWAY=192.168.1.1 DB=mariadb ./xwiki-lxc.sh --yes
```

## After the installation

| What | Where |
|------|-------|
| XWiki configuration | `/etc/xwiki/xwiki.cfg`, `/etc/xwiki/xwiki.properties` |
| Database connection | `/etc/xwiki/hibernate.cfg.xml` (generated by dbconfig-common) |
| Permanent data directory | `/var/lib/xwiki/data` |
| Tomcat heap / Java options | `/etc/default/tomcat10` (block `proxmox-script-xwiki`) |
| Logs | `journalctl -u tomcat10`, `/var/log/tomcat10/` |

**Updates:** XWiki is a normal Debian package, so updates come with
`apt update && apt full-upgrade` inside the container. Read the
[XWiki release notes](https://www.xwiki.org/xwiki/bin/view/ReleaseNotes/)
and take a backup or snapshot (`vzdump` / Proxmox Backup Server) first.

**Reverse proxy / HTTPS:** For production use, put XWiki behind a reverse
proxy with TLS (e.g. nginx, Caddy, Traefik). See the
[XWiki installation guide](https://www.xwiki.org/xwiki/bin/view/Documentation/AdminGuide/Installation/).

## How it works

1. `xwiki-lxc.sh` (runs on the host) validates the input, downloads the latest
   Debian 13 template with `pveam`, creates and starts the container with `pct`.
2. It copies `install/xwiki-install.sh` into the container and runs it.
3. The installer adds the XWiki APT repository with its signing key
   (`signed-by`), installs the database server and `xwiki-tomcat10-<db>`,
   lets `dbconfig-common` create the database with a random password, sets
   the Tomcat heap and waits until XWiki answers on port 8080.
